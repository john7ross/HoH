# Политика безопасности

[English](SECURITY.md) · **Русский**

## Область

HoH — локальный control plane. Облачные аккаунты моделей, vendor-сессии и
удалённые A2A-сервисы остаются внешними системами со своими политиками
безопасности.

## Границы безопасности

- Значения секретов не записываются в конфигурацию проекта, role profile,
  review bundle, метрики или journal. Хранятся только имена переменных среды,
  поэтому репозиторий не может утечь учётными данными.
- Ключ, который вы явно сохранили в интерфейсе, лежит в профиле пользователя вне
  проектов: под защитой DPAPI на Windows и с правами 0600 на остальных системах.
  Переменная окружения всегда имеет приоритет над сохранённым значением.
- Worker работает во временном Git worktree. Worker и Critic не могут commit,
  merge, push или закрыть задачу; интеграцию в canonical Git выполняет только
  Supervisor.
- Патч, allowed paths, команды проверки, решение Critic и Git identity связаны
  с неизменяемыми доказательствами. Перемещённый `HEAD` попытки блокируется.
- Состояние и операции репозитория используют разные lease. Повреждённая или
  неоднозначная запись блокирует новые изменения до решения оператора.
- Внешние A2A endpoints требуют HTTPS. Non-loopback headless binding требует
  переданных оператором TLS certificate/key и сильного API-токена. Push callback
  использует отдельный токен.
- Архивы управляемых агентов скачиваются только по HTTPS, требуют checksum из
  Registry и извлекаются с лимитами на traversal, ссылки, устройства, число
  файлов и общий размер.
- Обновления принимаются только через доверенный signed catalog с проверкой
  платформы, размера и SHA-256.

## Как сообщить об уязвимости

Сообщайте приватно на **Sergey Lebedev <john.spb.ross@gmail.com>** или через
приватные security advisories репозитория: <https://github.com/john7ross/HoH/security/advisories/new>. Не
публикуйте credentials, токены, приватные A2A URL или рабочий exploit в
открытом issue.

Приложите описание, версию и commit, шаги воспроизведения, ожидаемое влияние и
безопасный адрес для связи.

Подтверждение получения — в течение 7 дней, оценка — в течение 30 дней.
Пожалуйста, не раскрывайте уязвимость публично до выхода исправленной версии
или в течение 90 дней с момента отчёта — что наступит раньше.

## Чек-лист оператора

Используйте отдельное окружение для credentials провайдера, держите `*.env`,
ключи и сертификаты вне Git, оставляйте headless API на loopback, пока внешний
доступ не нужен, меняйте API/push-токены после передачи сервера и сохраняйте
queue/lease/audit evidence, необходимое для расследования неудачного запуска.
