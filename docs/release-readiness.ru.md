## Безопасность и корректность

### ✅ 1. Гейт области записи обходился, в том числе случайно на кириллице

Вся защита `allowed_paths` / `forbidden_paths` / traversal висела на одной
регулярке `^diff --git a/(.*?) b/(.*?)$`. Git C-экранирует этот заголовок для
любого не-ASCII имени, а обычный unified diff такого заголовка не имеет вовсе,
поэтому `changed_files` возвращался пустым и все три проверки проходили вхолостую.

Патч теперь разбирается по-настоящему: C-экранированные имена, заголовки
`---`/`+++`, combined diff, переименования (обе стороны), бинарные секции и тела
ханков, которые лишь выглядят как заголовки. Всё, что разобрать не удалось,
становится findings, а не молчаливым пропуском.

Воспроизведение до фикса: файл `секрет.yml` вне `allowed_paths=('src/',)`
проходил гейт с нулём замечаний. После фикса — `Patch changes files outside
allowed paths: секрет.yml`, файл в каноническом репозитории не появляется.

### ✅ 2. Пустой `allowed_paths` молча отключал проверку области

Теперь fail-closed. Явный маркер `"*"` разрешает весь репозиторий; схема плана
требует минимум один путь на задачу.

### ✅ 3. Строки от планировщика исполнялись через `shell=True`

Команды верификации пишет модель, а исполнялись они через shell с полным
окружением процесса, включая ключи провайдеров, в реальном репозитории
пользователя.

Теперь: argv без shell, allow-list запускаемых программ
(`[verification] allowed_commands`), интерпретаторы shell запрещены всегда,
неэкранированные операторы (`&&`, `|`, `;`, `>`) отклоняются вместо того чтобы
молча стать лишними аргументами, а окружение дочернего процесса очищается от
всего, что похоже на учётные данные. Команды, набранные оператором
(`rollback --check`, `audit --check`), сохраняют открытый список, но тоже
никогда не получают shell.

### ✅ 4. OAuth-токен мог уйти на plaintext `http://`

Удалённая Agent Card могла назвать token endpoint на `http://`, и клиентский
секрет уходил в открытом виде. Token/device/discovery endpoints теперь требуют
HTTPS; исключение — только loopback.

### ✅ 5. `.deb` ставил 311 путей как `0777` под root

Причина: `cp -a` с Windows-монтирования переносит `0777`. Теперь режимы
выставляются явно (каталоги `0755`, файлы `0644`, shell-точки входа `0755`), а
сборка отказывается выпускать пакет, в котором остался world-writable путь.

Пересобрано и проверено: 444 записи, 0 world-writable, все `root/root`.

### ✅ 6. `escalated` был терминальным тупиком

Все пять переходов в `queued` были закрыты от `escalated`, а задача попадала
туда штатно при исчерпании попыток. Добавлен `resolve_escalation()`: обратно в
очередь с обнулённым счётчиком попыток или закрытие как `failed`, оба с
обязательной причиной оператора и записью перехода. Доступно как
`queue-resolve-escalation` и двумя кнопками на странице операций.

### ✅ 7. Self-update снимал бит `+x` — `hoh` окирпичивался на Linux/macOS

Распаковка zip теряет бит исполнения, а архивы PowerShell его вовсе не хранят.
Права восстанавливаются после распаковки; проверено на Linux.

### ✅ 8. Убийство дерева процессов работало только под Windows

На POSIX `terminate()` доставал только прямого потомка, и каждый упавший по
таймауту агент оставлял живыми `npx`/node, удерживающие worktree попытки.
Дочерние процессы теперь стартуют в собственной сессии и убиваются группой.
Тест на Linux подтверждает, что «внук» умирает.

### ✅ 9. Кириллический дифф терялся на Windows с русской локалью

Вывод дочерних процессов декодируется как UTF-8 с откатом на кодировку ОС.

### ✅ 10. `git apply` получал патч с переписанными переводами строк

Найдено живым прогоном. `begin_task` восстанавливал ожидаемый post-image,
передавая патч в `git apply` через текстовый stdin; на Windows это превращает
каждый `\n` в `\r\n`, и контекст ханка не совпадает ни с одной строкой
LF-файлов. **На Windows очередь падала на первой же задаче** с «Could not derive
expected post-image from worker patch». Регрессионный тест проверен мутацией.

## Честность продукта

### ✅ 11. Документация заявляла сертификацию, которой нет

README, `docs/release.md` и `docs/harness-ecosystem.md` утверждали, что сборка
live-сертифицирована с Codex ACP 1.7.0 / gpt-5.4 по всем трём ролям.
`compatibility-matrix` показывает ноль live-certified записей для отпечатка
контроллера 1.0.0. Заявление снято на обоих языках, приведена команда проверки.

### ✅ 12. `role-conformance` выдавал «live-certified» внутреннему стабу

Сертификация отклонялась для любого драйвера с safety profile
`in-process-test-only`; прогон возвращал `status=not-certified` с причиной.
Позже вся схема сертификации была удалена целиком — см. пункт 32.

### ✅ 13. `doctor` давал зелёный свет конфигурации, которая не работает

На дефолтном конфиге Supervisor и verifier — стабы, Worker — тестовый драйвер.
Эти проверки теперь `warning`, в первой строке выводится их число, и печатается
конкретный следующий шаг, включая `bootstrap-runtime` для чистого клона.

### ✅ 14. Механизмы, которые ничего не делали

- `worker_trust_level` заявлял три уровня Git-полномочий; реализован один.
  Остальные отклоняются при загрузке конфига с объяснением.
- `documentation_updated` вычислялся поиском слова «documentation» в
  acceptance criteria, то есть сообщал о том, что задача просила, а не о том,
  что произошло. Теперь измеряется по самому патчу.
- `hoh notify` печатал `ok=True`, положив сообщение в выброшенный список.
  Без настроенного канала теперь `ok=False`, `delivered=False` и причина.
- Уведомления об эскалации предлагали `реши сам` и `свой`, которые ни один
  обработчик не выполняет. Теперь перечисляются только существующие команды, а
  `/delegate` прямо отвечает, что HoH не решает за оператора.
- `docs/sdlc.md` перечислял ручные шаги ревью среди обязательных проверок
  аудита. Разделено на то, что проверяет `llm-harness audit`, и то, что остаётся
  за оператором.

### ✅ 15. Документация расходилась с кодом

- `docs/architecture.ru.md` описывал шесть несуществующих модулей.
- `ARCHITECTURE.md` ссылался на карту модулей, которой не было.
- `README.ru.md` называл `rework` решением Critic.

Карты модулей переписаны по реальному дереву; каждое имя в обеих картах
проверено на существование.

## Интерфейс

### ✅ 25. Не было DPI-awareness

Процесс не объявлял себя DPI-aware, а окно было константой `1180x760`. На 4K при
100 % это треть ширины экрана с нечитаемым 9 pt; при 150–200 % Windows растягивала
окно битмапом.

Теперь: per-monitor DPI awareness до создания первого окна Tk, `tk scaling` из
реального DPI дисплея, размер окна от экрана и запоминание выбранного размера.
На машине разработки 4K/150 % это `1680x1050` при scaling 2.0 вместо размытых
`1180x760`.

### ✅ 26. 35 констант `wraplength` обрезали русский текст

Ширины подбирались под английские строки в Segoe UI 9 pt. Русский длиннее на
15–30 %, поэтому подпись запрашивала больше места, чем есть в карточке, и
обрезалась посреди слова. Ширина переноса теперь уменьшается до реальной ширины
контейнера при каждой раскладке, а спроектированная ширина остаётся верхней
границей.

### ✅ 27. Шрифты были захардкожены

`Segoe UI` в 27 местах молча заменялся системным на Linux/macOS. Стек шрифтов
разрешается один раз по семействам, которые Tk действительно сообщает, с откатом
на bold там, где semibold-семейства нет. На Linux выбирается `Ubuntu`.

### ✅ 28. `hoh gui` на headless-системе падал сырым `_tkinter.TclError`

Теперь объясняет, что нужен графический дисплей, и предлагает CLI или
headless-сервер.

### ✅ 29. Ошибки показывались текстом исключения

## Второй заход: структурный риск и церемония

### ✅ 30. Сквозной прогон теперь в CI

Дефекты №1 и №10 нашлись только когда продукт запустили на настоящей задаче.
Причина, по которой их не поймали 451 тест, точная: единственный тест, доходивший
до ledger'а, использовал патч вида `--- /dev/null`. У такого патча нет строк
контекста, поэтому `git apply` применяет его успешно даже с испорченным
конвейером.

Добавлен `tests/test_live_cycle.py`: отдельный процесс-worker по реальному
транспорту, правки **существующих** файлов, несколько файлов на задачу, ребро
зависимости и задача-нарушитель scope. Проверяются результаты, а не механика:
библиотека действительно изменилась и её тесты проходят, зависимая задача
выполнилась второй, нарушитель отклонён и его файл не появился, worktree чист,
ровно два коммита Supervisor, финальный аудит зелёный.

Проверено мутациями: возврат текстового stdin для `git apply` его роняет,
отключение проверки `allowed_paths` тоже. Идёт в обычном наборе тестов, то есть
CI выполняет его на Linux, Windows и macOS. 5,6 с на Windows, 11,9 с на Linux.

### ✅ 31. Сертификация убрана

Механизм хранил подписанные записи, привязанные к хешу исходников самого
контроллера. Для pet-проекта это церемония не по размеру, и она же породила
дефект №11: записи пережили код, который удостоверяли, а документация продолжала
заявлять сертификацию, которой у сборки уже не было.

Удалён `certification.py` (339 строк), хранилище `certifications-v1.json`,
отпечаток контроллера, четырёхуровневый словарь статусов и шаг «Live-сертификация»
в первом запуске. Вместо него `agent_matrix.py`: `available` / `unavailable` —
что установлено на этой машине.

`role-conformance` остался и стал полезнее: это диагностика «прогони роль в
одноразовом репозитории и скажи, работает ли». Раньше он отказывался работать,
пока не укажешь `--agent`, `--model` и `--agent-version`; теперь неизвестная
идентичность просто сообщается как `unknown`, а прогон происходит. В GUI кнопка
на карточке роли называется «Проверить роль».

### ✅ 32. Интерфейс перерисован

Скругления со сглаживанием (попиксельный расчёт покрытия угла, кэш плиток),
мягкие тени с подъёмом при наведении, кнопки с анимацией и состоянием нажатия,
собственные выпадающие списки вместо ttk-комбобоксов. Без сторонних зависимостей.

### ✅ 33. Ключи провайдера задаются в интерфейсе

Ключ можно было передать только переменной окружения, выставленной вне
приложения: интерфейс спрашивал *имя переменной* и дальше молча ничего не делал,
пока эта переменная не появится.

Добавлен `secret_store.py`: значение хранится в профиле пользователя — под DPAPI
на Windows и с правами 0600 на остальных системах, по файлу на имя. Конфигурация
проекта по-прежнему хранит только имена, поэтому репозиторий не может утечь
ключом, а переменная окружения всегда имеет приоритет над сохранённой — CI и
запуски по расписанию не затронуты.

### ✅ 34. Doctor запускается сам

Это была кнопка, которую надо было не забыть нажать, поэтому проект мог стоять в
состоянии, в котором задача не выполнится, и на экране об этом ничего не было.
Теперь проверка идёт при загрузке проекта, а в статусной строке одна строка:
готов, либо конкретный следующий шаг.

### ✅ 35. Первый запуск — три шага

Было около двенадцати действий на четырёх экранах. Стало: **Проект → Команда →
Задача**. Установка агентов и назначение ролей — следствия выбора команды, а не
отдельные обязанности оператора: их делает одна кнопка «Подготовить команду».

Остальное (агенты и подключения, MCP, настройки, проекты, метрики, операции) не
спрятано — оно перечислено на той же странице блоком «Всё остальное — когда
понадобится» и доступно из бокового меню. Пользователи разного уровня получают
разный путь, но короткий путь теперь есть.

### ✅ 36. Починен зависон интерфейса, найденный при этих правках

Карточка задавала себе ширину по содержимому, а содержимому — по своей ширине.
Внутри колонки с `uniform` эти двое расходились на один пиксель и
перекладывались бесконечно, подвешивая GUI на странице ролей. Ширина теперь
течёт в одну сторону. Инвариант закреплён тестом, проверенным мутацией: баг
проявляется зависанием, поэтому тест, который его *ждёт*, завис бы сам.

### ✅ 37. Эталонная проверка вёрстки предполагала масштаб 100 %

Smoke проверяет, что чат помещается в «обычное десктопное окно», и эталоном была
константа `1180x760` **в пикселях**. При DPI-масштабе 2.0 эти же числа описывают
окно с вдвое меньшим полезным местом: канва 568 px против нужных 612 px, и
проверка падала на совершенно нормальной вёрстке.

Эталон теперь задан в точках и переводится в пиксели по масштабу самого дисплея.
Проверено на 4K/150 %: эталон 2361×1520, чат помещается; мутация (высота
транскрипта 8 → 40 строк) проверку роняет, то есть она не вырождена.

### ✅ 38. «Подготовить команду» упиралась в незакэшированный реестр

Проверка установленности агентов и их установка были на месте и работают: все
агенты всех трёх пресетов находятся в ACP Registry и ставятся через `npx`. Но на
машине, которая ни разу не кэшировала реестр, шаг падал с «ACP Registry is not
cached. Refresh the registry first» — то есть ровно тем обходом, ради устранения
которого первый запуск и сокращали.

Теперь реестр забирается по месту, если кэша нет. Проверено на чистом кэше:
39 записей, кэш появился. Статусная строка сообщает, сколько агентов поставлено
сейчас и сколько уже было.

### ✅ 39. Патч терял возврат каретки в репозитории с CRLF

Оба места, где читается текст патча, шли через текстовый режим `subprocess`, а он
переводит переводы строк. Каждый CRLF из `git diff --cached` и из
`git show --binary` приходил как LF, и собранный патч переставал совпадать хоть с
одной строкой файла, из которого был снят.

На репозитории с LF-блобами это не видно, поэтому весь набор тестов проходил на
Windows (`core.autocrlf=true`) и на Linux. Вылезло на macOS-чекауте, где
`core.autocrlf` не задан: живой трёхролевой цикл умирал на первой же задаче с
«Could not derive expected post-image from worker patch: patch does not apply».

Второе место опаснее первого: в review-бандле патч хешируется, так что критик
подписал бы патч, которого в коммите не было.

Оба чтения переведены на байты с ручным декодированием. Закреплено фикстурой
с CRLF-репозиторием в каждом из модулей; проверено мутацией — с возвращённым
текстовым режимом тест падает. Тест `doctor`, который спрашивал у настоящего
`PATH` наличие агента, теперь подставляет резолвер: его исход зависел от того,
стоит ли на машине `npx`.

### ✅ 40. Запуск CLI внутри macOS-приложения был сломан

Генерируемый `scripts/hoh.sh` поднимался на два каталога от
`Contents/Resources/hoh/scripts` и попадал в `Contents/Resources`, то есть звал
`Contents/Resources/MacOS/HoH`, которого нет. Документированный способ попасть в
CLI из установленного приложения падал с «No such file or directory». Нужно три

Сборка теперь запускает лендер, который только что записала, на том же
одноразовом конфиге `doctor`, который и так использует: неверное число «..»

Найдено ровно так, как и должно: DMG собран на macOS 15.1, примонтирован, и
запущено то, что запустил бы пользователь.

### ✅ 42. Windows-инсталлятор нельзя было собрать

Сборка падала на собственном аудите. За этим стояли три отдельных дефекта.

Гейт запускал `set PYTHONPATH=src&& runtime\python\python.exe -m unittest ...`.
Это синтаксис cmd.exe, а проверочные команды давно исполняются без оболочки.
Строка никогда не превращалась в корректный argv — тесты, которые она называла,
не запускались ни разу.

Политика команд это пропускала. Она сравнивала целые слова argv со списком
операторов, поэтому оператор с пробелом рядом отклонялся, а склеенный — `src&&` —
проходил и становился мёртвым аргументом программы `set`. Ровно тот тихий
полупрогон, ради запрета которого правило и существует. Теперь разбор идёт
лексером, знающим о пунктуации: кавычки он уважает, так что `?a=1&b=2` внутри
аргумента по-прежнему допустим.

Дальше аудит падал. `subprocess` бросает `FileNotFoundError` на отсутствующую
программу, и это никто не ловил: одна незапускаемая проверка давала трейсбек
вместо находки, а остальные проверки не выполнялись. Теперь это код 127.

Тест, который должен был всё это ловить, грепал скрипт на подстроку
`PYTHONPATH=src` и ни разу не запускал команду. Теперь он прогоняет каждую
команду гейта через политику.

### ✅ 43. В инсталлятор уезжал путь сборочной машины

этого отказывается архивировать любой файл, называющий корень проекта.

Тест обходит все файлы под гитом и падает, если какой-то содержит путь чекаута,
в котором лежит.

### ✅ 49. `.deb` вёз байткод сборочной машины

В пакете лежали 83 файла `.pyc`, и каждый хранит абсолютный путь, из которого был
скомпилирован — `/home/<сборщик>/hoh-src/...`. То есть в трейсбеке у пользователя
печатались бы каталоги сопровождающего. Набор тестов, который этот же скрипт и
прогоняет, создаёт байткод, так что он попадал в каждую сборку.

Windows-сборка отказывается от скомпилированного байткода с самого начала и ровно
по этой причине. В `package-deb.sh` такого гейта не было, а чек-лист при этом
утверждал, что путей сборочной машины нет ни в одном артефакте. Утверждение было
неверным.

DMG чист: PyInstaller собирает код сам, а в ресурсы попадает только документация.
Затронут был только `.deb`. Теперь `__pycache__` удаляется из staging, и сборка
отказывается и от оставшегося байткода, и от любого файла, называющего корень
проекта.

Найдено сравнением двух пакетов: собранный на настоящей Ubuntu оказался вдвое
меньше собранного в WSL, и разница была именно в чужих `__pycache__`.

### ✅ 50. `.deb` был единственным пакетом без своего Python

Windows-установщик и macOS-бандл несут интерпретатор внутри. `.deb` полагался на
системный, и это исключало три реальных случая:

- **машина без сети** — `python3-tk` имеет приоритет `optional` и по умолчанию не
  стоит, apt не может его добрать, `dpkg -i` падает на зависимости;
- **дистрибутив старше Python 3.11** — на Ubuntu 22.04 LTS (поддержка до 2027)
  системный Python 3.10, и apt отказывается ставить пакет вообще;
- **минимальный образ или контейнер** — то же самое с Tk.

Теперь интерпретатор внутри пакета, из зависимостей остался только `git`.

Собирать его на машине сборки нельзя: на Ubuntu 26.04 glibc 2.43, и бинарник
потребовал бы её же — то есть «самодостаточный» пакет не запустился бы ни на
24.04 (glibc 2.39), ни на 22.04 (2.35). Взята релокативная сборка
python-build-standalone: старший glibc-символ в ней — 2.17. Релиз и контрольная
сумма закреплены по архитектурам, скрипт `scripts/bootstrap-runtime.sh`
симметричен одноимённому PowerShell-скрипту.

Две детали, которые легко упустить и обе проверены: проход `chmod 0644` по всем
файлам снял бы бит исполнения с интерпретатора и его разделяемых библиотек —
пакет установился бы и не работал; а удаление `__pycache__` из стандартной
библиотеки интерпретатора заставило бы её перекомпилироваться при каждом запуске
в каталог, куда пользователь не может писать. Байткод сборщика по-прежнему
вычищается — исключена только стандартная библиотека самого интерпретатора.

Отдельно закрыт разрыв, который это изменение создало: payload обновления не нёс
интерпретатор, а `/usr/bin/hoh` отдаёт управление самообновлённой копии, как
только она появится. Обновление заменило бы рабочую самодостаточную установку на
дерево, ищущее системный Python, которого на этой машине нет. Теперь payload
несёт рантайм и честно называет его в манифесте.

Проверено до того, как что-либо писалось: интерпретатор сообщает Python 3.11.16 и
Tk 9.0, весь набор — 533 теста — и GUI-смоук во всех четырёх сочетаниях проходят
на нём. После сборки: `Depends: git`, установленный лаунчер запускается на
`/opt/hoh/runtime/python/bin/python3`, `doctor` на конфиге с BOM даёт `ok=True`,
GUI 4 из 4. Размер пакета вырос с 344 КБ до 24 МБ — это и есть вложенный Python.

## Проверено живым прогоном

Полный трёхролевой цикл на настоящей задаче, а не на «создай файл из четырёх
строк». Проект: библиотека разбора строки биллинга с собственными тестами.
Три задачи, ребро зависимости и намеренное нарушение области записи.

- `quote-aware-split` — реальное изменение кода (переход на `csv.reader` для
  учёта кавычек) плюс два новых теста; Supervisor создал коммит.
- `document-quoting` — зависела от первой, дождалась её, изменила только README.
- `out-of-scope` — worker попытался создать `secrets.env` вне `allowed_paths`;
  гейт отклонил патч, файл в каноническом репозитории не появился, worktree
  остался чистым.
- Итоговая библиотека проходит свои тесты; финальный аудит — `ok=True`,
  0 findings, 46 событий журнала.

Именно этот прогон нашёл дефект №10, который на Windows блокировал очередь на
первой задаче.
