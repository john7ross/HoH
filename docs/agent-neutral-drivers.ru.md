# Вендоронезависимые драйверы

[English](agent-neutral-drivers.md) · **Русский**

## Текущая граница

Ядро HoH не выбирает поведение по именам продуктов вроде Hermes, Claude, Codex или OpenClaw. Оно
выбирает явный версионированный контракт драйвера для каждой из ролей Supervisor, Worker и Critic.
Любой соответствующий агент ACP Registry может занять любую из этих ролей без изменения кода HoH.
Доступность во время исполнения всё равно требует его лаунчера, аутентификации, учётных данных и
настройки модели.

Аудит экосистемы показал, что подходящей универсальной границей coding-агентов является ACP вместе с
официальным ACP Registry. См. `docs/harness-ecosystem.ru.md`. НеACP-шные одноразовые CLI используют
либо простой контракт `command` через stdin, либо декларативный контракт `process`; ни одна из этих
деклараций не является живым свидетельством, пока именно этот исполняемый файл и модель не пройдут
соответствие Worker'а.

Удалённые агенты используют вендоронезависимую границу A2A v1. Профиль может аутентифицироваться
через bearer, API-key, OAuth2 или OIDC; предпочитать потоковую передачу задач по SSE; подписываться на
долгую задачу; запрашивать аутентифицированный push-обратный вызов. Регистрацию клиента OAuth
по-прежнему предоставляет провайдер или оператор, тогда как HoH владеет обнаружением, входом с
устройства, обновлением токена, вырезанием секретов и хранением токенов в пользовательской области.
Эти возможности одинаковы для Supervisor, Worker и Critic; полномочия, специфичные для роли,
принуждаются адаптером вокруг транспорта, а не именем продукта-агента.

Для десктопного обратного вызова на loopback клиент A2A запускает аутентифицированный приёмник на
время запроса. Для внешне достижимого обратного вызова запустите задачу в серверном режиме HoH и
направьте провайдера на `/v1/a2a/push`; маршрут сервера и ожидающий адаптер делят один локальный для
процесса ящик входящих.

Обновить и изучить кэш официального ACP Registry:

```powershell
.\scripts\hoh.ps1 role-catalog --refresh-registry --json
```

Изучить установленные контракты драйверов HoH:

```powershell
.\scripts\hoh.ps1 driver-catalog --json
```

Каждая запись использует протокол `hoh.driver` версии `1.0` и объявляет свою роль, адаптер рантайма,
транспорт, контракт артефакта, требование изоляции, возможность субагентов и профиль безопасности.
Машинная схема — `schemas/driver-manifest-v1.schema.json`.

## Граница Supervisor

Supervisor больше не сводится к одной личности. У него три контракта исполнения:

- `model_json`: настроенный `[supervisor_model]` возвращает схемно-ограниченный план проекта;
- `command_json`: обычный процесс читает промпт планирования из stdin и выдаёт JSON project-spec;
- `acp`: ACP-harness планирует в пустом временном каталоге под политикой MCP для Supervisor; по
  умолчанию она отклоняет любое разрешение на инструмент и не даёт ни одного MCP-сервера.

Выбранный Supervisor может рассуждать и выдавать план, но изменением репозитория он не владеет.
Детерминированный control plane HoH по-прежнему владеет переходами очереди, применением патча,
проверкой, коммитами, откатом, аудитом и передачей.

## Граница Worker

Используйте `driver = "command"` для любого CLI-агента, который умеет:

1. запускаться неинтерактивно в текущем рабочем каталоге;
2. читать один ограниченный промпт задачи из stdin;
3. править файлы в этом каталоге;
4. завершаться кодом `0` после создания изменений-кандидатов;
5. воздерживаться от коммита, ветвления, merge, push, одобрения и общения с заказчиком.

HoH создаёт изолированный worktree `hoh/attempt/*`, даёт переменные окружения с метаданными `HOH_*`,
собирает получившийся diff Git, удаляет попытку, проверяет патч и в одиночку применяет и коммитит его
в канонический репозиторий. Stdout worker'а носит только диагностический характер; артефактом он не
считается.

```toml
[worker]
driver = "command"
command = "my-agent-cli"
args = ["run"]
timeout_seconds = 300

[[agents]]
name = "my-agent"
command = "my-agent-cli"
args = ["run"]
worker_driver = "command"
```

Имя агента — метаданные инвентаря и интерфейса. Контракт исполнения задаёт `worker_driver`.
Переименование агента или исполняемого файла выбор драйвера не меняет.

### Декларативные одноразовые профили процессов

Используйте `driver = "process"`, когда CLI нужен промпт в файле или обязательные неинтерактивные
аргументы и аргументы безопасности. Профиль — это данные в конфигурации проекта, а не код на Python.
Он объявляет:

- `prompt_transport`: `stdin` или `file`;
- `prompt_argument`: принадлежащий HoH флаг, помещаемый перед путём временного промпта при транспорте
  `file`;
- `required_args`: флаги, которые HoH всегда добавляет;
- `forbidden_args`: аргументы оператора, которые разрушили бы контракт безопасности;
- `model_argument`: принадлежащий HoH селектор модели, когда он поддерживается;
- `version_args`: не меняющие состояние аргументы пробы версии.

Пример собственного Worker'а в `.hoh/harness.json`:

```json
{
  "agents": [
    {
      "name": "my-headless-cli",
      "command": "my-headless-cli",
      "args": ["run"],
      "worker_driver": "process",
      "worker_process_profile": {
        "profile_id": "my-headless-cli-v1",
        "prompt_transport": "file",
        "prompt_argument": "--prompt-file",
        "required_args": ["--non-interactive", "--no-commit"],
        "forbidden_args": ["--commit", "--interactive"],
        "model_argument": "--model",
        "version_args": ["--version"]
      }
    }
  ]
}
```

HoH отклоняет настроенные аргументы, которые сталкиваются с флагами промпта и модели, совпадают с
запрещёнными флагами профиля или несут распространённые встроенные опции секретов вроде `--api-key` и
`--token`. Держите учётные данные в окружении запускающего процесса. Временный файл промпта удаляется
после завершения процесса; stdout и stderr — ограниченные диагностические свидетельства, а diff
файловой системы остаётся единственным артефактом-кандидатом.

В каталог по умолчанию входит Aider как декларативный профиль Worker. Его текущий профиль следует
документированному одноразовому контракту скриптования: `--message-file`, `--no-stream`, `--yes`,
`--no-auto-commits` и `--no-dirty-commits`; необязательная модель роли передаётся через `--model`.
Профиль появляется как выбираемый, только когда `aider` есть в `PATH`. HoH не хранит ключи провайдеров
и не устанавливает Aider автоматически.

Для каждого изолированного драйвера Worker HoH запоминает исходный коммит попытки и отклоняет
результат, если Worker сдвинул `HEAD` в Git. Это не даёт автоматически коммитящему CLI превратить свои
изменения в пустой собранный diff и сохраняет за Supervisor'ом исключительное владение коммитом
независимо от флагов CLI.

## Граница Critic

Используйте `driver = "model_json"` для прямого вендоронезависимого Critic. Он вызывает
`[verifier_model]` с теми же неизменяемыми свидетельствами и закрытой схемой решения, не передаёт пути
к репозиторию и записывает только свидетельства запроса и ответа с вырезанными секретами. HoH
поддерживает `openai`, `deepseek` и явный HTTPS-эндпоинт `openai_compatible`.

```toml
[verifier_model]
provider = "deepseek"
model = "deepseek-chat"
api_key_env = "DEEPSEEK_API_KEY"

[critic]
driver = "model_json"
command = ""
```

Используйте `driver = "command_json"` для любого ревьюирующего CLI только на чтение. HoH отправляет
неизменяемый промпт ревью и бандл в stdin. Процесс обязан записать в stdout один объект JSON ровно с
такими полями:

- `decision`: `approve`, `reject` или `escalate`;
- `summary`;
- `findings`;
- `correction_brief`;
- `escalation`.

HoH проверяет решение и сам прикрепляет доверенные идентификаторы бандла, хеши, метки времени,
личность и аттестацию. Critic не должен править файлы, вызывать инструменты проекта и коммитить.

```toml
[critic]
driver = "command_json"
command = "my-reviewer-cli"
args = ["review"]
timeout_seconds = 300
```

`manual` сохраняет границу экспорта и импорта файлов. `claude_code` — вложенный краевой драйвер,
принуждающий режим плана, отсутствие инструментов и отсутствие сохранения сессии.

Используйте `driver = "acp"`, чтобы выбрать Critic'ом любого агента ACP. HoH запускает его вне
репозитория, применяет политику MCP для Critic (по умолчанию отказ и отсутствие серверов), при
необходимости выбирает запрошенную модель ACP и принимает только закрытый контракт JSON решения.

## Граница провайдера моделей

Ролям модели Supervisor'а, семантического верификатора и прямого Critic доступны `stub`, `openai`,
`deepseek` и `openai_compatible`. OpenAI-совместимый эндпоинт использует контракт JSON Chat
Completions и обязан объявлять и `base_url`, и `api_key_env`; учётные данные в конфигурации не
хранятся никогда.

```toml
[supervisor_model]
provider = "openai_compatible"
model = "vendor-model"
base_url = "https://models.example.test/v1"
api_key_env = "VENDOR_MODEL_API_KEY"
```

HTTPS обязателен, кроме тестовых эндпоинтов на loopback.

## Профили ролей и совместимость

Профиль ролей v2 может нести явный `driver` рядом с `agent` и `model`. Если он опущен, HoH читает
явные `supervisor_driver`, `worker_driver` или `critic_driver` из выбранной записи каталога. Драйвер
из имени агента и базового имени команды он не выводит никогда.

Устаревший профиль ролей v1 по-прежнему читается. Устаревшие `[worker].type` и `[critic].type`
остаются принимаемыми псевдонимами. В новых конфигурациях следует использовать `driver`; если
присутствуют оба ключа, они обязаны разрешаться в один канонический драйвер.

Пример с тремя независимыми выборами:

```json
{
  "profile_version": "2.0",
  "critic_enabled": true,
  "max_attempts": 3,
  "roles": {
    "supervisor": {"agent": "claude-acp", "model": null, "driver": null},
    "worker": {"agent": "codex-acp", "model": null, "driver": null},
    "critic": {"agent": "qwen-code", "model": "<точный вариант DeepSeek в ACP>", "driver": null}
  }
}
```

Идентификаторы агентов разрешаются из закэшированного официального реестра. Строка модели не
угадывается: HoH спрашивает у выбранной ACP-сессии её варианты моделей и падает, если точного
запрошенного значения нет. Таким образом Codex может быть Worker'ом, а другой умеющий DeepSeek
harness — Critic'ом, но сам по себе DeepSeek — имя модели, а не личность harness'а. Для Critic без
harness'а выберите цель каталога `direct-critic-model`; личность её провайдера и модели берётся из
`[verifier_model]`.

## Как добавить агента без изменений ядра

1. Для ACP запустите `role-catalog --refresh-registry` и используйте идентификатор реестра напрямую.
   Для неACP-шного процесса добавьте запись `agents[]` с командой, аргументами, окружением и явными
   драйверами ролей. Используйте `worker_process_profile`, если размещение промпта или обязательные
   флаги безопасности отличаются от stdin.
2. Запустите `doctor`, чтобы проверить конфигурацию и обнаружение исполняемого файла.
3. Запустите `worker-smoke` для неживой предполётной проверки.
4. Запустите `worker-conformance --config ...` или `worker-smoke --live` в одноразовом репозитории.
5. И только тогда используйте драйвер на настоящем проекте.

Если агент не может удовлетворить `command` или `process`, добавьте новый краевой адаптер и
версионированную запись реестра. Не импортируйте произвольный сторонний Python в процесс Supervisor'а:
держите учётные данные провайдеров, сессии и специфичную для агента логику безопасности по ту сторону
границы процессов.
