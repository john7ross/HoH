# Уборка рабочего пространства HoH

[English](workspace-cleanup.md) · **Русский**

## Правило безопасности

Уборка ведётся по свидетельствам. До удаления проверьте активные процессы, запланированные задания,
worktree Git, настроенные корни состояния, записи сверки, статус очереди и ревью и то, не является ли
элемент единственной копией диагностических свидетельств. Покажите оператору точный список удаления и
получите явное одобрение. Не выводите одобрение из общей просьбы завершить проект.

## Срез инвентаря

Инвентарь ниже описывает закрывающий релиз аудит, выполненный 2026-07-20. Перед действиями проверки
нужно повторить, потому что состояние процессов, заданий, очереди и файловой системы меняется.

| Элемент рабочего пространства | Классификация | Свидетельство и причина |
| --- | --- | --- |
| `harness/` | сохранить | Канонический исходник Git, сборка, тесты, документация, встроенный рантайм, wheelhouse и релизные артефакты. |
| `.hoh-state/live-triad-smoke-*` | сохранить | Уникальные свидетельства очереди, истории, журнала и ревью; последний успешный прогон остаётся в `review_pending` без импортированного решения. |
| `live-triad-smoke/` | сохранить | Чистый замороженный репозиторий Git с успешным коммитом Hermes, на который ссылается ожидающий review-бандл. |
| `.hoh-leases/` | сохранять, пока репозиторий управляется | Корень координации во время исполнения. Текущий файл блокировки harness — метаданные; активность определяет состояние блокировки ОС, а не возраст файла. |
| `.hoh-attempts/` | удаляемо, если при перепроверке пусто | Пустой порождённый корень попыток; HoH создаёт его заново. До одобрения оператора не удалять. |
| `.tmp-live-critic/` | заархивировать или удалить после одобрения | Фикстура неудавшегося живого теста Hermes и Claude; ни коммита, ни решения ревью. Полезна только как отрицательное свидетельство о провайдере. |
| `.tmp-live-critic-stub/` | заархивировать или удалить после одобрения | Завершённая детерминированная фикстура заглушки с личностью Claude и одобренным решением. Она доказывает автомат состояний ревью, но не живой вызов Claude. |
| `ralph/` | заархивировать или удалить после одобрения | Чистый отдельный апстримный чекаут, использовавшийся только как справочник по дизайну; ни рантайма, ни сборки, ни пакета, ни процесса, ни задания, ни ссылки из исходников. |
| Корневые Markdown и PDF по дизайну и `3headDevelopment.md` | заархивировать или удалить после одобрения | Перекрытые историей входные материалы; текущие контракты живут в `harness/docs`. Входами рантайма и пакета они не являются. |
| `harness/build/`, `*.egg-info`, `__pycache__`, `.tmp/` | порождённое и удаляемое | Кэши сборки и интерпретатора; не отслеживаются и создаются заново командами сборки и тестов. |
| `harness/runtime/`, `vendor/`, `dist/` | сохранить для релиза | Игнорируемые порождённые промышленный рантайм и поставляемые артефакты. Пересобирать только документированными скриптами. |
| `harness/graphify-out/` | заархивировать или удалить после одобрения | Локальный граф анализа, не вход сборки, рантайма и пакета. Может пригодиться для будущей археологии кода. |

## Перепроверка только на чтение

```powershell
git -C C:\path\to\repo worktree list --porcelain
git -C C:\path\to\repo status --short
Get-CimInstance Win32_Process |
  Where-Object { $_.CommandLine -like '*C:\path\to*' }
Get-ScheduledTask |
  Where-Object { $_.TaskName -like '*HoH*' -or $_.TaskPath -like '*HoH*' }
.\scripts\hoh.ps1 lock-status --project-root C:\path\to\repo --json
.\scripts\hoh.ps1 reconcile-status --project-root C:\path\to\repo --json
```

Для каждого корня состояния изучите также очередь, историю, ревью, решения, откаты, аудиты и статус
сверки, используя соответствующий ему канонический репозиторий. Если канонического репозитория больше
нет, сохраните корень состояния, пока сирота не будет понят и явно не получит решения о судьбе.

## Выполнение одобренной уборки

После явного одобрения удаляйте только названные элементы, чья классификация и состояние были
перепроверены. Используйте буквальные абсолютные пути и убеждайтесь, что каждый путь остаётся под
`C:\path\to`, до рекурсивного удаления. Не применяйте широкое удаление по маске. Составьте инвентарь
после уборки и повторите хеши релизных артефактов и канонический аудит чистого worktree.
