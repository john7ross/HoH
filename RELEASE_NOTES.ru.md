# HoH 1.0.0

[English](RELEASE_NOTES.md) · **Русский**

HoH — локальный десктопный и headless control plane для трёхролевого процесса с
ИИ: Supervisor, Worker и Critic. У каждой роли может быть свой агент, своя
модель и свой драйвер связи.

## Что скачивать

| Платформа | Файл | Примечания |
|---|---|---|
| Windows 10/11 x64 | `HoH-Setup-1.0.0.exe` | Установщик для текущего пользователя. Authenticode не подписан, поэтому SmartScreen может предупредить о неизвестном издателе. |
| Ubuntu/Debian x86_64 | `hoh_1.0.0_amd64.deb` | Установите системным менеджером пакетов. Из зависимостей объявлен только `git`. |
| macOS x86_64 | `HoH-1.0.0.dmg` | Перетащите `HoH.app` в Applications. Сборка подписана ad-hoc, поэтому Gatekeeper заблокирует первый запуск: на macOS 15 и новее откройте **Системные настройки → Конфиденциальность и безопасность** и нажмите **Открыть всё равно** под сообщением о HoH; на более старых macOS — Finder → правая кнопка → **Открыть**. |

Все три пакета несут собственные Python и Tk. Ничего доустанавливать не нужно, и
для установки не требуется сеть.

Загружайте вместе с установщиками соответствующие файлы `.sha256` и манифест
Windows. Именно в этих файлах лежат авторитетные значения SHA-256; проверьте их
до установки:

```bash
sha256sum -c hoh_1.0.0_amd64.deb.sha256
shasum -a 256 -c HoH-1.0.0.dmg.sha256
```

## Что входит в 1.0.0

- Десктопный GUI и аутентифицированный headless-сервер для Windows, Linux и macOS.
- Русский и английский интерфейс, светлая и тёмная темы, адаптивная раскладка и пошаговый мастер первого запуска.
- Независимое назначение ролей Supervisor, Worker и Critic с поддержкой обычного ACP v1.
- Обновление ACP Registry, управляемая установка агентов в пользовательскую область, передача вендорского входа и проверки доступности с отказом на старте.
- Удалённые подключения A2A v1 с обнаружением Agent Card, аутентификацией bearer/API-key/OAuth2/OIDC, потоковой передачей SSE, аутентифицированным push и ограниченным откатом на опрос.
- Политики MCP по ролям, очередь и история проекта, повторы и восстановление, метрики, запуски по расписанию, уведомления рабочего стола и необязательные уведомления в Telegram.
- Подписанный каталог обновлений с установкой рядом, свидетельства совместимости, Doctor, проверка соответствия протоколу и команды финального аудита.

## Что проверено

Каждый пакет собран из этого коммита, а затем установлен и запущен на своей
операционной системе, а не только на той машине, где его собирали:

| | Windows 11 Pro | Ubuntu 26.04 | macOS 15.1 |
|---|---|---|---|
| Набор тестов | 559 пройдено | 559 пройдено | 559 пройдено |
| Установка из артефакта | тихая, на чистый профиль | `dpkg -i` | DMG смонтирован, подпись проверена, приложение скопировано в Applications |
| CLI после установки | `doctor` ok на конфигурации с меткой порядка байт | так же | так же |
| Конформанс после установки | `protocol-conformance`, `three-head-conformance`, `workflow-smoke` — все ok | так же | так же |
| Смоук GUI, язык × тема | 4 из 4 | 4 из 4 | 4 из 4 |
| Встроенный интерпретатор | Python 3.11.15, Tk 8.6 | Python 3.11.16, Tk 9.0 | Python 3.12.10, Tk 8.6 |

Деинсталлятор Windows тоже проверен: после него не остаётся ни каталога, ни
ярлыка в меню «Пуск», ни записи в списке установленных программ.

Именно эти проверки на живых операционных системах выявили три последних дефекта
релиза: ни один пакет не нёс уведомлений о сторонних лицензиях; сценарии сборки
не запускались в том PowerShell, который поставляется с Windows; внутри бандла
macOS любая операция GUI открывала вторую копию приложения вместо запуска
команды. Все три исправлены в перечисленных выше артефактах.

Пакет для Linux работает на glibc 2.17 и новее, то есть покрывает Ubuntu 20.04 и
Debian 11 и старше.

## Что не утверждается

- **Запустившийся пакет — не работающая учётная запись у вендора.** Работает ли
  у вас конкретный агент, отвечает запуск `role-conformance --role <роль>` на
  вашей машине, а не этот релиз.
- Windows Setup не подписан Authenticode, а сборка macOS не нотаризована. Оба
  предупреждения выше ожидаемы для сборки без платной подписи.
- В свидетельствах этого релиза нет живого трёхролевого прогона на коммерческом
  провайдере; последняя попытка упёрлась в лимит квоты провайдера.

## Сторонние компоненты

Установщики несут внутри CPython, Tcl/Tk, OpenSSL, SQLite, zlib и несколько
меньших библиотек, каждая под собственной лицензией. Они перечислены в
[`THIRD-PARTY-NOTICES.ru.md`](THIRD-PARTY-NOTICES.ru.md). У собственного
исходного кода HoH сторонних зависимостей времени выполнения нет.

## Замечание о развёртывании A2A

Локальный ACP не требует ни домена, ни публичного TLS-сертификата, ни клиента
OAuth. Удалённому A2A всё это нужно только тогда, когда провайдер должен
достучаться до HoH снаружи машины. HoH проверяет HTTPS для эндпоинтов не на
loopback и умеет терминировать TLS, когда оператор предоставил сертификат и
ключ; DNS, выпуск публичного сертификата и регистрация OAuth-клиента у
провайдера остаются настройкой на стороне оператора или провайдера.
